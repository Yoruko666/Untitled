# 共享状态与模块存档整合

本次同步同时保留远端共享状态、开发调试工具和本地模块存档；以下说明更新两份早期设计文档中的状态所有权约定。

## 运行状态

- `GameData` 是唯一运行状态，持有日期、阶段、金币、仓库、探索包裹、订单 ID 集合、当前订单进度、剧情、解锁和地下标记。
- `GameSession` 包装同一个 `GameData`，负责模块快照转换、恢复就绪状态和通知，不再持有第二份日期、阶段或剧情数据。
- `GamePhase.Shop` / `Day` 共用数值 0，`Underground` / `Night` 共用数值 1，保留已有存档中的枚举数值。`Settlement` 保留，但场景恢复入口会明确拒绝尚未实现的结算流程。
- HUD 接收统一状态通知；场景原有昼夜主题和外部提供的展示信息继续保留，仓库沿用共享库存的变更事件。

## 两种已有文件格式

- `GameManager.TrySave/TryLoad` 保留 `shared-game-v1.json` 格式；初始化时仍尝试读取这个文件，不切换场景。新快照补齐当前订单进度和地下标记，旧文件缺少这些字段时恢复为空状态。
- `SaveManager.Save/LoadAsync` 保留 `Saves/slot_0.json` 的校验和、备份恢复和阶段场景恢复流程。模块快照补齐包裹与已接/已完成订单集合；旧模块文件缺少新增字段时按空集合恢复。
- 两个入口操作同一个运行状态，但文件仍独立，不自动相互覆盖或按时间选择文件。读取模块槽位仍需显式调用 `LoadAsync`；模块存档继续限制日期为 1–7。
- 模块读档使用库存的恢复 API，即使容量配置降低，也保留合法的已有物品；未知物品沿用共享库存规则跳过并提示。
- 调试修改后的会话禁止通过上述两个普通保存入口覆盖文件；模块恢复尚未完成时，也禁止共享格式入口保存或加载。

## 检查

- 使用当前 Unity 自带编译器和项目缓存引用，运行代码通过 Editor、Release、Development（启用调试工具）三种编译检查，Editor 工具与现有测试代码也通过编译，均无编译警告。
- 独立托管执行通过已有库存数量/容量、状态快照、新游戏、快照隔离、无效输入检查，以及本次状态投影、模块恢复、容量降低、旧字段兼容、场景失败回滚和双保存入口调试保护检查。
- 在现有 `SharedGameVerification` 中补充状态投影与模块文件往返检查，在开发工具验证中补充模块保存保护。`SaveSystemTests` 的无效金币用例改为向存储层提供无效快照，适配金币只读接口。
- 本次未运行 Unity Editor 内的测试、原生 `JsonUtility` 文件往返、Play Mode 或完整构建。独立托管检查不能替代这些验证。

人工验收可在 Editor 退出 Play Mode 后运行 `Untitled/Shared Game/Development Tests/Run Data Checks`，再试玩仓库/HUD 与存读档恢复。
