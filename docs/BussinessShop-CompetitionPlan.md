# Bussiness 比赛版精简方案

本次交付为空间设计与 Unity 执行方案，尚未调整 Scene、Prefab 或玩法代码。方案依据当前保存的 `Bussiness.unity`、组装工具、模型尺寸清单及上一轮实际游玩截图；没有进行新的 Editor 或 Play Mode 验证。

## 1. 推荐空间结构

将现有 8 × 9 米室内缩为 **5.8 × 4.4 米，净高保持 3.2 米**。面积从 72 平方米降到 25.52 平方米，减少约 65%。保留模型原始米制比例，通过减少家具与移动墙体压缩空间，不整体缩放房间根节点或玩家。

采用「后墙连续工作台 + 右侧仓储 + 右后地下门」布局。制作、封杯、包装、出杯在同一侧完成；订单板位于工作台上方。前侧只保留店门、一个窗口和招牌等店铺暗示，不设置独立就餐区。

俯视关系图（示意，不按比例；+Z 为后侧，+X 为右侧）：

```text
                     后墙 +Z
┌──────────────────────────────────┐
│      订单板                      │
│ [茶底 / 小料][封杯 / 包装 / 出杯] │
│                                  │
│            ↑ 出生朝向      地下门│
│          PlayerSpawn             │
│                            仓储柜│
│                                  │
│     小窗口        店门 / 招牌     │
└──────────────────────────────────┘
                     前侧 -Z
```

中央地面保持连续；操作站位与设备前缘间留约 0.7–1 米。关键路线净宽以至少 1.1 米为目标，地下门周围和仓储前方不摆落地杂物。

现有 `work_counter` 为 1.795 × 0.900 × 0.671 米（宽 × 高 × 深），两张并排即可组成约 3.6 米长的连续台面。现有 `basement_portal` 为 2.330 × 2.555 × 0.873 米，应放在右侧墙后段；不缩成小门，不贴在封杯台末端，也不压低层高。

## 2. 场景改造步骤

1. 退出 Play Mode，记录当前 Scene/Prefab 状态；将现有 Bussiness 场景另存备份，再建立比赛版环境 Prefab `bussiness_shop_competition_room.prefab`。保留旧环境资产，避免改动共享道具 Prefab。
2. 移除场景中的两套餐桌椅、长凳和顾客区地面杂物；删除额外柜台、独立水槽、POS 与相应非核心站点。
3. 重建 5.8 × 4.4 米地板，移动四面墙、护墙板、天花与横梁。保留完整碰撞边界；减少地板块数和重复装饰。不要整体缩放原 8 × 9 米环境。
4. 后墙并排两张工作台：左侧茶底与小料，右侧封杯与包装；空杯放在两区连接处，出杯托盘放在右端。所有设备操作面朝中央员工区。
5. 将订单板移到制作区上方。将仓储柜移到右侧近处，地下门移到右后侧；旧闭门碰撞体与门模型一起移动、旋转并检查对齐。
6. 重新布置出生点和站点接近位置；出生朝向制作区。让封杯机只占视野右侧，避免门、订单板或大型杯架占据画面中心。
7. 精简灯光到两个操作区暖光与一个较弱背景补光；地下入口用克制的绿色标识提示方向。保留奶油白、浅木、抹茶绿和已有低多边形材质。
8. 更新 `ShopSceneBindings` 的站点数组及出生引用，保存新环境 Prefab 与 Bussiness 场景；从实际出生点进行一次连续行走、射线交互和截图验收。

## 3. 建议保留的物体

| 物体 | 建议数量 | 用途 |
|---|---:|---|
| `work_counter` | 2 | 连续制作、封杯、包装台面 |
| `tea_dispenser_*` | 1–2 | 表达茶底选择，按首轮配方需求保留 |
| `ingredient_bins` 或 `topping_bin` | 1 组 | 表达核心小料操作，优先留出调配空位 |
| `cup_sealing_machine` | 1 | 清晰的封杯目标 |
| `paper_cups`、`takeout_bags` | 各 1 组 | 空杯与包装材料，靠近封杯机 |
| `finished_boba` | 1 组 | 出杯目标，放在独立托盘范围 |
| `notice_board` | 1 | 订单列表入口 |
| `storage_cabinet` | 1 | 仓库交互入口，不另建仓库房间 |
| `display_shelf`、`ingredient_jars` | 各最多 1 | 叠放在柜上，提示原料收纳 |
| `basement_portal` 和闭门碰撞 | 1 | 明确的地下目标 |
| `glass_double_door`、`wood_window`、`store_sign` | 各 1 | 表达奶茶店外观与顾客来源 |
| 吊灯、木梁 | 少量 | 操作区暖光与风格统一 |

糖浆、冰箱、搅拌机仅在当前比赛配方确实需要时加入；预留台面空位比摆满全部资产更优先。杯架可以由更小的纸杯组替代。环境暗示优先用墙面物件，不必保留座椅；若仍有余量，最多保留一处不侵入通道的装饰。

## 4. 建议删除的物体

- `square_table_set`、`round_table_set`、`wooden_bench` 及餐桌纸巾盒。
- 原五张工作台中的三张，独立 `sink_counter`、`pos_terminal`、收银操作站与取水操作站。
- 地面木箱、纸箱、麻袋、水果箱和挡路垃圾桶；必要的仓储提示放到柜上。
- 重复盆栽、藤蔓、菜单板、世界说明板、窗户、吊灯与横梁。
- 无核心配方用途的第三茶桶、重复小料盒、杯架和额外制作设备。

这里的删除指移除比赛场景实例；原 FBX、材质及可复用道具 Prefab 保留。

## 5. 玩家动线

主循环为：**看订单 → 制作 → 向右一步封杯 → 右端出杯**。查看订单主要通过抬头完成，制作到封杯主要横移，出杯不需要绕到顾客侧。补货从台面退一步后转向右侧仓储；前往地下则转向右后侧。

建议初始站位如下，坐标使用 (X,Y,Z) 米，Y=0.025 为玩家脚底位置；以下是待在 Editor 中落位检查的设计值。

| 点位 / 稳定 ID | 接近位置 | 交互朝向 |
|---|---|---|
| `PlayerSpawn` | (-0.65, 0.025, 0.15) | 朝 +Z 制作区 |
| `PreparationStation` | (-1.00, 0.025, 0.45) | 朝 +Z |
| `OrderBoard` | (-0.65, 0.025, 0.45) | 朝 +Z，略抬头 |
| `SealingStation` | (0.45, 0.025, 0.45) | 朝 +Z |
| `DeliveryPoint` | (1.05, 0.025, 0.45) | 朝 +Z，略低头 |
| `StoragePoint` | (1.65, 0.025, -1.15) | 朝 +X |
| `DungeonEntrance` | (1.20, 0.025, -0.10) | 朝 +X，右后侧门扉 |

制作到封杯约横移 1.45 米；出生到仓储约 2.65 米，为最远的关键点。按当前 2.8 米/秒速度估算，纯行走通常约 0.2–1 秒；计入转身、找准目标，设计目标为 **每个关键点 1–3 秒到达并开始交互**。这些是布局估算，尚未在新布局中实测。

## 6. Unity 执行方案

### 空间和物体落位

原点设在室内平面中心，净边界 X∈[-2.9,2.9]、Z∈[-2.2,2.2]，地面 Y=0，天花内表面 Y=3.2。墙厚建议保持 0.20–0.24 米；坐标以模型锚点为初始值，落位后再依据 Renderer.bounds 和 Collider.bounds 对齐内墙。

| 对象 | 初始位置 (X,Y,Z) | Y 轴朝向 | 落位说明 |
|---|---|---:|---|
| 左工作台 | (-1.35,0,1.65) | 0° | 制作设备归属左台 |
| 右工作台 | (0.45,0,1.65) | 0° | 与左台间距约 5 毫米 |
| 封杯机 | (0.45,0.90,1.65) | 0° | 沿用后侧台的面向方式；以实际操作面校验 |
| 出杯模型 / 托盘 | (1.05,0.90,1.38) | 0° | 靠台面前缘，袋子放后侧，避免碰撞重叠 |
| 订单板 | (-1.10,1.65,2.12) | 0° | 底边 1.65 米，中心约 2.10 米；避开茶桶遮挡 |
| 仓储柜 | (2.62,0,-1.15) | 90° | 操作面向 -X，柜前保持空地 |
| 地下门模型 | (2.45,0,0.55) | 90° | 门宽沿 Z 展开；按实际锚点贴右墙 |
| 玩家 | 同 `PlayerSpawn` | 0° | 眼位仍为 1.65 米 |

地下门旋转后占用右侧墙约 2.33 米长度，与仓储柜之间留约 0.18 米物体间隔；柜体向内投影较浅，门前路线从中央直达。门模型锚点可能偏移，不能只以名义尺寸判断最终碰撞。需要确认石拱最内侧与右工作台之间无夹缝可卡住玩家。

初始视野沿用现有 65° FOV，可将眼部初始俯角设为约 10–15°并同步控制器的初始 pitch；最终以出生画面中茶底、小料和空台面占据中央为准，不把仰头查看订单的需求当成默认出生朝向。

### 交互层级与接口

复用 `ShopFirstPersonController`、`ShopRaycastInteractor`、`ShopStation`、`ShopSceneBindings`。五种核心玩法对应六个站点：制作、封杯、出杯、订单、仓储、地下入口；封杯与出杯保持各自 ID，方便后续流程接入。

- 保留 `PreparationStation`、`SealingStation`、`DeliveryPoint`、`OrderBoard`、`StoragePoint`、`DungeonEntrance` 的稳定 ID。
- 从比赛场景和绑定数组移除 `OrderCounter`、`WaterStation`；不删除或重排 `ShopStationKind` 枚举，避免影响其他场景的序列化值。
- 保留 `CustomerSpawn` 为店门附近的非玩法标记，接口不需要为了删座椅而修改。
- 工作台碰撞作为公共家具归组；设备、订单板、出杯托盘的碰撞分别放在对应 `ShopStation` 子层级。避免整条台面归属某个站点，导致准星对着出杯处却触发制作。
- 无 Collider 的杯子和袋子若需要独立交互，应在对应站点添加小型实体 BoxCollider；现有射线忽略 Trigger，不能用 Trigger 充当交互目标。
- 所有保留站点均通过 `ShopSceneBindings.StationRequested` 或 Inspector UnityEvent 接入后续系统；本次空间精简不实现配方、订单状态、消耗、金币或地下加载。

建议比赛版环境层级：`Architecture`、`Worktops`、`Stations`、`LayoutPoints`、`Lighting`、`ShopHints`。新环境 Prefab 与场景保存摆放，运行时不重建布局。原 `BussinessShopBuilder` 是旧场景的一次性组装工具，不直接重复执行其 Build 来覆盖现有编辑结果。

### 灯光与视觉

先保留现有 URP 材质和 ACES，操作台设置两盏暖光，中心覆盖制作及封杯；只让主操作光承担必要阴影，背景补光更弱。把现有五处吊灯减至两处，并避免吊灯垂入玩家中央视线。

通过灯光覆盖范围使工作台明显亮于前侧背景，以约 1.5–2 倍视觉亮度为初始目标。右后地下门使用低强度绿色提示或明确标识，保持在工作台之后的视觉层级。亮度与颜色最终按 Game 视图检查；不同时调整全项目曝光、材质或渲染资产。

### 验收与保存

1. 从出生点连续走到全部六个站点，确认路线无绕路、夹缝和落地杂物阻挡，目标为 1–3 秒内开始交互。
2. 六个站点各用中心射线和 E 检查一次，确认反馈与对应站点事件；订单板不被设备挡住，出杯不误触制作，门和墙不允许穿出。
3. 检查出生画面中央为制作区，截取出生、封杯、地下门三张实际 Game 画面；退出 Play Mode，保存 Prefab 与 Scene，核对引用和当前任务 diff 后本地提交。

## 修改范围与当前状态

落地实施预计涉及 `Assets/Scenes/Bussiness.unity`、新增比赛版环境 Prefab 及 `.meta`；如需独立后处理配置，再新增比赛版 Profile。原道具模型、既有 FPS Prefab、地下城控制器和场景均不需要修改。

目前新增的只有本方案文档。尺寸、路线时间和灯光强弱是执行目标，不代表新场景已改造或已通过试玩。当前交互仍为占位反馈；“前往地下”保留场景切换接入点，实际地下加载需由后续流程任务接通。
